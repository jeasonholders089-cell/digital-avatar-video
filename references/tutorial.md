# 数字人口播视频制作教程

本文对应项目当前已经验证的工作流：**文本 → 本人原声音频 → HeyGen Avatar III 单次连续渲染 → 同源音频生成字幕 → 自动与人工质检**。

## 1. 先明确边界

这个流程解决的是“用自己的数字分身持续制作口播视频”，不是把一段短视频循环播放，也不是把一条长视频拆成许多段再拼起来。后两种做法很容易产生：

- 每隔几秒回到开头画面；
- 分段接缝跳变；
- 头部动作突然改变；
- 口型和字幕分别对应不同时间轴；
- 重编码后出现频闪或音频偏移。

因此，长视频的第一原则是：**完整音频一次驱动完整视频**。

## 2. 一次性准备

### 2.1 项目环境

在项目根目录 `.env` 中配置：

```dotenv
HEYGEN_API_KEY=你的密钥
```

密钥只供本地脚本读取，不要写进 Python、Markdown、Git、日志、截图或聊天回复。生成前通过 API 查询余额；余额不足就停止，不自动充值。

### 2.2 个人数字分身

1. 在 HeyGen 创建并完成本人授权的 Digital Twin。
2. 确认目标 look 已完成，并确认该 look 支持 Avatar III。
3. 记录 look ID 到本地脱敏状态文件；不要把它硬编码到 Skill 或教程中。
4. 形象素材尽量满足：正脸、头部居中、光线稳定、无遮挡、无明显镜头变化。

`avatar group ID` 是分身集合标识，不能直接作为生成请求中的 `avatar_id`；生成时使用具体的 `look ID`。

### 2.3 本人声线

先准备一条已经确认“确实是本人”的声线。此前出现女声的根本原因不是口型算法，而是音频链路选错了声线。处理规则是：

- 用户提供录音：直接把录音作为最终驱动音频，必要时只做响度、采样率和静音头尾处理。
- 用户只提供文本：使用已确认的本人声线生成音频，然后播放试听。
- 不要因为 API 请求方便而使用 avatar 默认声线。
- 在提交数字人任务前固定音频文件，并计算 SHA-256。

## 3. 从文本到最终音频

### 3.1 文案先按“说话”改写

口播文本不要直接照搬长文章。建议：

- 一句话只承载一个主要意思；
- 数字、英文缩写和专有名词先确认读法；
- 在自然停顿处使用逗号和句号；
- 每段读完后留出可听见但不突兀的停顿；
- 先把文本读出声，凡是自己会卡顿的地方，先改文案而不是等模型修。

### 3.2 冻结音频

生成后检查：

```text
audio_sha256 = SHA256(audio_file)
audio_duration = duration(audio_file)
```

把以下信息写进本地 journal：

```json
{
  "script_sha256": "<text-hash>",
  "audio_sha256": "<audio-hash>",
  "audio_duration_seconds": 60.91,
  "voice_reference": "<approved-voice-label>",
  "status": "audio_frozen"
}
```

此后所有步骤都引用这份音频。不要在 HeyGen 生成后临时换音频，也不要用另一份音频生成字幕。

## 4. 上传音频并创建 Avatar III 视频

如果 HeyGen 还没有这份音频资产，先通过资产上传接口上传，保存返回的 `audio_asset_id`。相同文件的 asset ID 可以复用，避免重复上传；如果本地哈希变了，就视为新音频重新检查。

当前项目采用 HeyGen v3 的视频生成接口。请求结构如下，字段值均为占位符：

```bash
curl -X POST "https://api.heygen.com/v3/videos" \
  -H "x-api-key: $HEYGEN_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: <stable-request-key>" \
  -d '{
    "type": "avatar",
    "avatar_id": "<digital-twin-look-id>",
    "audio_asset_id": "<audio-asset-id>",
    "engine": { "type": "avatar_iii" },
    "aspect_ratio": "auto",
    "resolution": "1080p",
    "output_format": "mp4"
  }'
```

这里的 `audio_asset_id` 和 `script` 二选一；本流程选择音频，是因为用户已经确认自己的原声，并且音频能同时作为口型和字幕的时间基准。接口是异步的，成功提交后会返回 `video_id`，不代表视频已经完成。

### 4.1 幂等和费用保护

提交前按下面的字段生成稳定请求键：

```text
hash(look_id + engine + audio_sha256 + aspect_ratio + resolution + output_format)
```

顺序必须是：

1. 查询余额；
2. 检查本地是否已有同一输入的 `video_id`；
3. 把请求摘要和幂等键写入 journal，状态设为 `submitting`；
4. 发起一次提交；
5. 得到 `video_id` 后只查询该任务。

如果请求超时、连接断开或响应无法解析，结果属于“未知”，不能立刻重新发起第二次付费请求。先查任务状态、任务列表和余额；确认原任务不存在后，才由用户决定是否重试。

## 5. 轮询、下载和保存母版

使用同一个 ID 查询：

```text
GET https://api.heygen.com/v3/videos/<video_id>
```

建议轮询间隔 10–15 秒，并设置总超时。状态处理：

| 状态 | 处理 |
| --- | --- |
| `waiting` / `pending` / `processing` | 继续查询，不重复提交 |
| `completed` | 读取视频地址，立即下载本地母版 |
| `failed` | 保存错误码和错误摘要，停止收费操作 |

下载后的文件至少记录：路径、字节数、SHA-256、时长、宽高和帧率。推荐命名：

```text
master-avatar-iii-<duration>-<date>.mp4
```

不要覆盖原始输入视频，也不要覆盖已有母版。母版应保持无字幕，便于后续更改字幕样式而不重新消耗数字人额度。

## 6. 生成与烧录字幕

字幕必须从“驱动数字人的同一份音频”生成：

1. 用本地 Whisper 或 faster-whisper 转写音频；
2. 保留词级或片段级时间戳；
3. 按语义和画面宽度合并成字幕句段；
4. 输出 SRT；
5. 需要固定样式时输出 ASS；
6. 用 FFmpeg 把 ASS 烧录到母版，原音轨直接映射保留。

字幕不要遮挡嘴部。中文通常控制在一到两行；不要把整段长句压成一条字幕，也不要把每个字单独闪现。字幕版输出另存为：

```text
captioned.mp4
captions.srt
captions.ass
```

## 7. 成片质检清单

### 7.1 自动检查

- 音频存在且可以解码；
- 视频时长与音频时长差不超过约 `0.25s`，目标是更小；
- 前、中、后多个时间区间的音轨偏移为 `0ms` 或在可接受误差内；
- 输出分辨率、帧率和画幅符合任务要求；
- 顶部若干像素带没有持续黑线；
- 相邻帧没有异常的大幅差分峰值；
- 字幕文件时间范围覆盖完整音频，最后一句不提前消失。

### 7.2 人工播放检查

至少检查：开头、约 20–30 秒、约 40–50 秒和结尾。重点看：

- 说话时嘴部是否在动，停顿时是否自然闭合；
- 爆破音、快速连续音节、数字和英文是否容易错位；
- 是否出现频闪、纹理抖动或脸部细节跳变；
- 是否突然扭头、姿态跳变、回到首帧或出现多余动作；
- 是否有顶部黑块、裁切错误、过重磨皮或画面变糊；
- 字幕是否与实际语音同时出现，并且没有遮嘴。

自动化可以证明“音轨时间轴一致”，但不能单独证明每个音素对应的嘴形都正确。因此报告中要分别写：

```text
audio_timeline_alignment: pass / fail
phoneme_to_viseme_review: pass / needs_manual_review
```

## 8. 常见问题和根因

| 现象 | 根因 | 修复方向 |
| --- | --- | --- |
| 成片变成女声 | 使用默认 voice 或错误声线资产 | 回到最终音频，核对声线和哈希 |
| 10 秒正常，60 秒接缝跳 | 把短片段分段生成再拼接 | 使用完整音频一次连续生成 |
| 每隔几秒出现开头画面 | 循环了短动作素材 | 禁止循环，直接使用连续渲染 |
| 字幕和嘴型都不对 | 字幕或视频用了另一份音频 | 从同一份冻结音频重新生成两者 |
| 顶部黑线 | 画幅、源素材或缩放处理不一致 | 先检查原始分辨率，再做明确裁切/缩放 |
| 脸部频闪 | 模型细节抖动、分段接缝或重复编码 | 先定位来源，确认后再决定是否重渲染 |
| 动作太大、扭头 | 使用了带动作参考或不适合的输入 | 固定正脸、轻微自然动作；必要时换引擎或重新评估素材 |

## 9. 交付格式

最终交付不要只给一个视频文件。建议目录结构：

```text
output/<job-name>/
├── master.mp4
├── captioned.mp4
├── captions.srt
├── captions.ass
├── qc.json
├── journal.json
└── README.md
```

`journal.json` 只保存脱敏信息：哈希、状态、任务 ID、时长和检查结果。不要保存 API Key、授权 URL、完整远程媒体 URL 或完整 API 响应。
